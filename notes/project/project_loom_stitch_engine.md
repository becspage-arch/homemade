A real **yarn-level stitch engine** for crochet (and knitting) inside the loom, built 2026-06-29. Replaces hand-authored per-stitch geometry (which doesn't scale — every render read as rope/food/dumplings/knots). Rebecca pushed for the real thing; this is it and it works. See [[project_loom_engine_build_state]], [[render_process_canonical]], [[feedback_customer_eye_renders]], [[feedback_render_before_volume]].

**The core idea — ONE continuous strand.** The fabric is a single unbroken yarn traced exactly as a hook lays it (down into the stitch below, under its top, back up, throw the loop, on to the next), then **relaxed** so the interlock is the yarn physically passing under the loop below — NOT separate "stitch pieces" joined by springs. This is what scales to complex stitches (a cluster/post/cable is just "what the one yarn does next") and to 3D (same path on a curved surface).

**Five stages:** stitch dictionary → connectivity/topology → form (2D plane now; 3D surface later) → **relaxation** (the crux) → render.

**Relaxation (the crux + the risk):** position-based (Gauss-Seidel) with: distance constraints along the yarn, bending, **self-collision at one yarn diameter**, soft plane pull. Collision-at-diameter is what forces every loop open to a yarn-width so topology resolves into recognisable stitches; loops start topologically linked and stay linked (collision can't pass them through). Skip collision for bonded pairs + near-neighbours along the strand.

**Key model decisions that finally worked (sc):**
- Each stitch = a clean front **"V"** (visible, +z) with the row-to-row link routed **BEHIND** the fabric (−z, hidden by the backing plane) → front reads as a tidy V-grid, not a surface knot.
- **No ply twist in the path** (twist = rope/knot look); add a *gentle* twist only in the render plies for fibre.
- **Flat / low relief** + dense gauge for sc (high relief = "dumplings").
- A flatter **barred top** (not a sharp V) reads as crochet, not stockinette knit.

**Per-stitch process (do this for EVERY stitch):** get a real **reference photo** and LOOK at it → build it as one **continuous strand** → render → photoreal (upscale + gate, structure must hold) → judge **as a customer** → confirm across **weights**. Only keep what passes the customer eye.

**GENUINE-TOPOLOGY REWRITE (2026-06-29) — the only model going forward.** Earlier sc/hdc/dc leaned on a pin+spring trick (drawn post shapes pinned to a grid, rows joined by a distance spring) = faking the stitch formation; Rebecca caught it ([[feedback_no_faking_stitch_formation]]). Rebuilt so the yarn is genuinely stitched: ONE strand, TURNED each row (`dir` serpentine + `fz` worked-face flip = real right-side/wrong-side), each stitch hooks UNDER the crown below (dive to the far z-side of that crown), interlock held by self-collision — NO pins on worked stitches (only the foundation chain), NO springs. Post HEIGHT relaxes out of the yarn fed + firm bending (k≈0.7) + a "blocked flat" y-pull (`layoutK` in relax.ts). Gauge per-stitch (`sw`: sc~2.0yr dense, hdc~2.2, dc~2.5 open). Per-stitch features = "what the one strand does next" (hdc third loop = the start-of-stitch yarn-over laid across the head line). Renderer floats the fabric above the table + auto-places the backing under the lowest stitch (back-face rows go −z). Full method in handbook §8a.
