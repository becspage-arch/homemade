HARD RULE (Rebecca, 2026-06-29): before declaring ANY loom stitch/render good, **get a real swatch sample photo from the internet and visually LOOK at it side-by-side with our render.** Never call something a win from memory or from the render alone.

How to apply (every stitch, every time):
1. WebSearch for the stitch; WebFetch a tutorial page to get an actual swatch image URL.
2. Download it to local scratch (calibration only — internal fixture, gitignored, NEVER shipped/redistributed; link the source, don't republish) and `Read` it so you actually SEE it.
3. `Read` our render right after, in the same turn, and compare honestly: does ours read like the reference? Name the specific differences.
4. Only if a customer would be happy AND it matches the reference → bring it. Otherwise keep iterating.

Why: I kept declaring renders "good" that didn't match reality (the fpdc "earbuds in a row" vs a real dense raised-rib post-stitch fabric). Comparing to a real photo each time is the guard.

Builds on [[feedback_customer_eye_renders]] (look as a customer) and [[feedback_no_faking_stitch_formation]]. The user CANNOT see Read-tool images in their client — show our renders to them via clickable markdown links to the PNG. Reference images: link the source URL to them, never embed.
